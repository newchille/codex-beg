# Codex BEG for macOS — friend setup

This package is a self-contained **macOS Apple Silicon (arm64)** desktop app. For a normal team install, use `Codex-BEG-0.1.0-mac-arm64.dmg`; `Codex-BEG-mac-arm64.zip` remains a portable fallback. You do not need this source repository, Node.js, npm, pnpm, TypeScript, or Codex CLI.

This guide was checked against the current OpenAI Secure MCP Tunnel documentation on 2026-08-25. The public `openai/tunnel-client` release observed at that time was `v0.0.12`; always use the official latest-release link below rather than assuming a version.

## 1. Requirements

- Apple Silicon Mac (`arm64`) and macOS 11 or newer.
- ChatGPT access with Developer Mode / connector access enabled by the relevant workspace admin.
- Access to the OpenAI Platform organization that owns or is associated with the tunnel.
- An existing tunnel ID and a separate restricted Runtime API key.
- The Runtime API key principal must have Tunnels **Read** + **Use** for the target tunnel.
- The tunnel must be associated with the ChatGPT workspace where the connector will be created.

The two important values are different:

```text
CONTROL_PLANE_TUNNEL_ID=tunnel_0123456789abcdef0123456789abcdef  # identifier, not secret
CONTROL_PLANE_API_KEY=<runtime secret>                            # secret
```

Official pages:

- [Secure MCP Tunnel guide](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)
- [Platform Tunnels](https://platform.openai.com/settings/organization/tunnels)
- [Runtime API keys](https://platform.openai.com/settings/organization/api-keys)
- [Latest tunnel-client release](https://github.com/openai/tunnel-client/releases/latest)
- [ChatGPT Plugins](https://chatgpt.com/plugins)

## 2. Install Codex BEG

1. Open `Codex-BEG-0.1.0-mac-arm64.dmg`.
2. Drag `Codex BEG.app` to `Applications` (your user Applications folder is fine).
3. Eject the DMG and open the app from Finder.

If using the ZIP fallback, unzip `Codex-BEG-mac-arm64.zip` first and then drag `Codex BEG.app` to `Applications`.

This distribution is not notarized with a Developer ID. If macOS blocks it, use the normal UI path: right-click `Codex BEG.app` → **Open**. If it is still blocked, open **System Settings → Privacy & Security** and choose **Open Anyway** for this app. Do not disable Gatekeeper globally.

## 3. First launch

1. Open `Codex BEG.app`.
2. Open **Doctor** → **Run checks**.
3. Confirm the Agent Host is running and the MCP endpoint is:

   ```text
   http://127.0.0.1:43123/mcp
   ```

4. If the app was left open while its Agent Host became stale, use **Doctor → Restart Agent Host**. Do not open a second Codex BEG instance.

The internal Agent Host admin token is generated by the app. It is not an OpenAI key, is not user-configured, and must not be copied into this guide or into tunnel-client configuration.

## 4. Install tunnel-client

Use one of these official methods.

### Option A — official Homebrew tap

If Homebrew is already installed:

```bash
brew install openai/tools/tunnel-client
tunnel-client --version
tunnel-client help quickstart
```

### Option B — Platform or official release download

Download the macOS arm64 client from [Platform Tunnels](https://platform.openai.com/settings/organization/tunnels) or [openai/tunnel-client Releases](https://github.com/openai/tunnel-client/releases/latest). Put the downloaded executable somewhere on your user PATH, for example `~/bin/tunnel-client`, then run:

```bash
mkdir -p "$HOME/bin"
chmod 700 "$HOME/bin/tunnel-client"
export PATH="$HOME/bin:$PATH"
tunnel-client --version
tunnel-client help quickstart
```

Do not download a random Homebrew formula or third-party binary. Codex BEG intentionally does not bundle or manage tunnel-client.

## 5. Get the tunnel ID

Open [Platform Tunnels](https://platform.openai.com/settings/organization/tunnels), select the tunnel that should serve this Mac, and copy its `tunnel_id`.

Set it in the terminal as a non-secret value:

```bash
export CONTROL_PLANE_TUNNEL_ID='tunnel_0123456789abcdef0123456789abcdef'
```

The real value must be `tunnel_` followed by 32 lowercase hexadecimal characters. Do not use the tunnel name in place of the ID.

If you have an admin key and actually need tunnel CRUD, the official CLI family is `tunnel-client admin tunnels ...`. You do not need an admin key just to connect to an existing tunnel.

## 6. Get a Runtime API key

Ask the Platform organization owner/RBAC administrator for a separate key for this Mac. In [Runtime API keys](https://platform.openai.com/settings/organization/api-keys), create a **Restricted** key with only:

- Tunnels: **Read**
- Tunnels: **Use**

The key's principal must also be allowed to use the target tunnel. The ChatGPT connector operator needs the same Read + Use access to select the tunnel.

`OPENAI_ADMIN_KEY` is a different, higher-privilege concept used for tunnel CRUD such as create/list/update/delete. Do not use or share an owner's admin key for the local daemon. Do not share another person's Runtime API key; request a separate restricted credential if the organization's policy permits it.

## 7. Store/set the key safely

### A. Temporary, current terminal only

This avoids putting the secret itself into shell history:

```bash
printf 'Runtime API key (input hidden): '
IFS= read -r -s CONTROL_PLANE_API_KEY
printf '\n'
export CONTROL_PLANE_API_KEY
```

Keep this terminal open while using the foreground `tunnel-client run` flow. Do not paste the key into a chat, screenshot, profile, or command-line argument.

### B. Recommended, user-only secret file

The current client supports `file:/path/to/secret` and `env:VARIABLE_NAME` secret references. Create a file readable only by your macOS user:

```bash
KEY_FILE="$HOME/.config/codex-beg/secrets/control-plane-api-key"
install -d -m 700 "$HOME/.config/codex-beg/secrets"
umask 077
printf 'Runtime API key (input hidden): '
IFS= read -r -s CONTROL_PLANE_API_KEY
printf '\n'
printf '%s' "$CONTROL_PLANE_API_KEY" > "$KEY_FILE"
unset CONTROL_PLANE_API_KEY
chmod 600 "$KEY_FILE"
stat -f '%A %N' "$KEY_FILE"
```

Expected permissions are `600`. The file must contain only the key, with no label or quotes. Never put the literal key in a YAML profile or in this guide.

## 8. Connect the existing tunnel to Codex BEG

First make sure Codex BEG is open and its local endpoint responds:

```bash
curl -fsS http://127.0.0.1:43123/healthz
```

For a long-lived local runtime, use the official managed-runtime flow:

```bash
KEY_FILE="$HOME/.config/codex-beg/secrets/control-plane-api-key"
export CONTROL_PLANE_TUNNEL_ID='tunnel_0123456789abcdef0123456789abcdef'

tunnel-client runtimes connect \
  --alias codex-beg \
  --tunnel-id "$CONTROL_PLANE_TUNNEL_ID" \
  --runtime-api-key "file:$KEY_FILE" \
  --mcp-server-url http://127.0.0.1:43123/mcp
```

Do not use `nohup` or `disown` as the recommended supervision path.

If this binary does not provide the `runtimes` command family, use the documented named-profile path instead:

```bash
KEY_FILE="$HOME/.config/codex-beg/secrets/control-plane-api-key"
export CONTROL_PLANE_API_KEY="$(<"$KEY_FILE")"
export CONTROL_PLANE_TUNNEL_ID='tunnel_0123456789abcdef0123456789abcdef'

tunnel-client init \
  --sample sample_mcp_remote_no_auth \
  --profile codex-beg \
  --tunnel-id "$CONTROL_PLANE_TUNNEL_ID" \
  --mcp-server-url http://127.0.0.1:43123/mcp

tunnel-client doctor --profile codex-beg --explain
tunnel-client run --profile codex-beg
```

The profile flow stays attached to the current terminal. Keep it running while creating or testing the ChatGPT connector.

## 9. Verify tunnel-client

For the managed runtime:

```bash
tunnel-client runtimes list
tunnel-client runtimes status codex-beg
tunnel-client runtimes status codex-beg --json
```

Only treat setup as successful when status reports the managed runtime running with health surfaced. When the client exposes its local health listener (default `127.0.0.1:8080`), also run:

```bash
curl -fsS http://127.0.0.1:8080/healthz
curl -fsS http://127.0.0.1:8080/readyz
open http://127.0.0.1:8080/ui
```

`/healthz` means the process is alive. `/readyz` is the important connector check: it should be HTTP 200 before testing ChatGPT. If the managed status output gives a different health URL, use that URL instead.

## 10. Create the MCP app/plugin in ChatGPT

1. Leave Codex BEG and the healthy tunnel runtime running.
2. Open [ChatGPT Plugins](https://chatgpt.com/plugins).
3. Click `+` to create a developer-mode app (some workspaces show **Apps → Create** instead).
4. Choose **Tunnel** under Connection.
5. Select the available tunnel or paste the same `tunnel_id`.
6. Enter the app metadata, click **Scan Tools**, then **Create**.
7. Open a new chat and select the draft app from the Tools menu to test it.

The tunnel must be associated with the target ChatGPT workspace, not only with a Platform organization. ChatGPT Developer Mode is a separate workspace permission.

## 11. Test a Codex BEG tool call

Start read-only:

1. Confirm the app Doctor page says Agent Host is running.
2. Confirm local `healthz` and tunnel `/readyz` are HTTP 200.
3. In ChatGPT, select the Codex BEG connector.
4. Ask for `workspace_list`.
5. Confirm a read-only result.
6. Only then register a project.
7. A workspace registration/expansion should show an explicit capability-grant approval; approve it only when the exact directory is correct.

Do not begin with writes, Git commits, recovery restores, or other destructive operations.

## 12. Starting again after reboot

Codex BEG starts its local Agent Host when the app opens. After a reboot:

```bash
open -a "Codex BEG"
curl -fsS http://127.0.0.1:43123/healthz
tunnel-client runtimes status codex-beg --json
```

Do not assume either process is persistent across reboot without checking. If the managed runtime is not running/healthy/ready, run the `runtimes connect` command from section 8 again. This guide does not install a LaunchAgent automatically.

## 13. Stopping the tunnel

For a managed runtime:

```bash
tunnel-client runtimes stop codex-beg
tunnel-client runtimes status codex-beg --json
```

You can leave Codex BEG open, but ChatGPT calls will not work until both the app and a healthy tunnel runtime are available again.

## 14. Troubleshooting

### App does not open

- Open it from Finder; do not launch a source-repository command.
- Right-click → **Open** once.
- If blocked, use **System Settings → Privacy & Security → Open Anyway**.
- Confirm the Mac is Apple Silicon: `uname -m` should print `arm64`.
- Do not disable Gatekeeper or remove quarantine globally.

### “Developer cannot be verified”

Use the normal Finder/UI recovery above. This is an unsigned/adhoc development distribution, not a notarized Developer ID release.

### Agent Host offline or port 43123 unavailable

```bash
curl -i --max-time 3 http://127.0.0.1:43123/healthz
lsof -nP -iTCP:43123 -sTCP:LISTEN
```

Quit another Codex BEG instance if one owns the port, then open one app instance and use **Doctor → Restart Agent Host**. Do not kill an unknown PID or start a second Agent Host.

### `401` from local admin routes

This is expected without the app's internal admin token:

```bash
curl -i --max-time 3 http://127.0.0.1:43123/admin/state
```

Do not try to configure or copy an Agent Host admin token. The app keeps it inside Electron main and uses it only for its own trusted UI bridge.

### `tunnel-client: command not found`

```bash
command -v tunnel-client
brew install openai/tools/tunnel-client
tunnel-client --version
```

If Homebrew is not installed, use the macOS arm64 binary download from Platform Tunnels or the official latest release link in section 4, then put it on `PATH`.

### Runtime API key missing

```bash
tunnel-client help quickstart
tunnel-client doctor --profile codex-beg --explain
test -r "$HOME/.config/codex-beg/secrets/control-plane-api-key" && stat -f '%A %N' "$HOME/.config/codex-beg/secrets/control-plane-api-key"
```

Do not print the key with `cat`, `echo`, or `env`. If using the managed flow, check that the `file:` path is correct and readable by your user.

### Tunnels Read/Use permission missing

Ask the Platform organization owner/RBAC administrator to grant the Runtime API key principal Tunnels **Read** + **Use** for this tunnel. Role changes can take time to propagate. Do not substitute an admin key.

### Tunnel ID is wrong

Confirm the value in Platform Tunnels management. It must be the same ID used by the connector and runtime, in the form `tunnel_` plus 32 lowercase hexadecimal characters.

### Runtime launched but is not ready

```bash
tunnel-client runtimes status codex-beg --json
curl -i --max-time 3 http://127.0.0.1:43123/healthz
curl -i --max-time 3 http://127.0.0.1:8080/healthz
curl -i --max-time 3 http://127.0.0.1:8080/readyz
open http://127.0.0.1:8080/ui
```

Check that the MCP URL is exactly `http://127.0.0.1:43123/mcp`, the app is open, and the runtime key can use the target tunnel.

### Tunnel is visible in Platform but not in ChatGPT

- Associate the tunnel with the target ChatGPT workspace.
- Confirm the connector operator has Tunnels **Read** + **Use**.
- Confirm the runtime is healthy and `/readyz` is HTTP 200.
- If the tunnel was just created or changed, allow propagation time.

### ChatGPT shows stale MCP tools or calls fail after a schema change

1. Use **Doctor → Restart Agent Host**.
2. Confirm `healthz` shows a live Agent Host.
3. Refresh/reconnect the ChatGPT connector so it discovers the new catalog.
4. Re-test with `workspace_list` before any write.

### Sleep/reboot breaks calls

Open Codex BEG again, check port 43123, then check:

```bash
tunnel-client runtimes status codex-beg --json
```

If it is not running/healthy/ready, reconnect it using section 8. The remote tunnel object can still exist while the local runtime is stopped.

## 15. Uninstall / cleanup without deleting project files

1. Stop the managed runtime:

   ```bash
   tunnel-client runtimes stop codex-beg
   ```

2. Quit Codex BEG.
3. Move `Codex BEG.app` to Trash from Finder.
4. If you want to remove only the local secret, verify the path first and remove that secret file from Finder or with an explicit user-approved cleanup action. Do not remove any project/repository directory.
5. Do not delete the OpenAI tunnel unless you are the tunnel owner and intentionally want to remove it for every user/device.

## 16. Security notes

- Never share `CONTROL_PLANE_API_KEY` or `OPENAI_ADMIN_KEY` in chat, screenshots, tickets, or this guide.
- Use a separate restricted Runtime API key per device/person when policy permits.
- `OPENAI_ADMIN_KEY` is for tunnel CRUD, not the normal runtime daemon.
- The local MCP server stays on loopback at `127.0.0.1:43123`; do not expose that port publicly.
- Codex BEG does not store the tunnel runtime key and does not bundle tunnel-client.
- The app's internal admin token is generated per session and is not user-configured.
- Start with read-only MCP calls. Workspace expansion is capability-grant approved; writes and destructive actions require the app's safety flow.
- No raw shell MCP tool, generic process-start tool, filesystem delete tool, or destructive Git reset/clean tool is provided.
